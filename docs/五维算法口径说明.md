## 0. 前置条件

| 项 | 规则 |
|---|---|
| 参与计算的会话 | `finished = sessions.filter(s => totalStudySec(s) > 0)`，即 **总学习 = 总时长 − 休息 − 暂停 > 0** |
| 展示门槛 | `sampleCount = finished.length >= MIN_SAMPLES = 3`；不足则页面显示「🌱 还在了解你」，**不渲染任何数值** |
| 落库 | 每次 `endSession()` 后重算并写入 `focus_profile` 表 |

### 共用口径（五个维度都建立在这几个数上）

```
已判定时长 judgedSec(s) = focusDuration + distractionDuration
                          （净专注 + 分心，不含答疑 / 休息 / 暂停）

专注率   netFocusRate(s) = focusDuration     / judgedSec(s)
分心率   distractionRate(s)= distractionDuration / judgedSec(s)
                          → 两者相加恒等于 1

完成率   completionRate(s) = 已完成任务 / 承诺任务    （无任务清单时返回 0）
```

> ⚠️ 注意：`netFocusRate` 的分母**不是**「总学习」，而是「已判定」。这是为了让答疑时间不压低专注率——答疑期间状态不参与"专注还是分心"的判定。这个改变同时意味着 **专注率 + 分心率 ≡ 1 恒成立**，下面第 3 节会用到。

## 1. 逐维算法

### ① 专注度 concentration = `round( weightedRate )`

```
netSec    = Σ focusDuration           （全部 finished 会话）
judgedSec = Σ (focusDuration + distractionDuration)
weightedRate = netSec / judgedSec × 100
concentration = round(weightedRate)
```

- **口径**：跨会话**按时长加权**的净专注率
- 与复盘页「总体专注率」是同一个数
- **独立维度**

### ② 效率 efficiency = `round( 0.6 × weightedRate + 0.4 × execution )`

- 用的是**未取整的** `weightedRate`，而 `execution` 是**已取整**的值
- **派生维度**：取整前精确等于 `0.6 × 专注度 + 0.4 × 执行力`，不含任何新信息

### ③ 稳定性 stability

```
rates[i] = netFocusRate(第 i 场会话) × 100      // 每场会话的专注率
σ        = stddev(rates) / 100                  // 总体标准差（除以 n，不是 n−1）
stability = σ > 0.3  ?  0
                     :  round( 100 × (1 − clamp(σ / 0.4, 0, 1)) )
```

- **口径**：各会话专注率的波动程度，σ 越小分越高
- **独立维度**
- 断点：σ > 0.3 → 直接 0（不是渐进到 0）

### ④ 执行力 execution

```
taskSessions = finished.filter(s => s.taskIds.length > 0)   // 只算有任务清单的会话
committed    = ∪ taskSessions.taskIds                        // 承诺过的任务（去重）
doneIds      = tasks.filter(t => t.done || t.status === DONE).map(t => t.id)
                                                // ★ 以任务表**当前状态**为准
execution = committed 为空 ? 0
                           : round( |doneIds ∩ committed| / |committed| × 100 )
```

- **口径**：用户承诺过要做、现在真正做完的任务比例
- 用任务表当前状态而不是 `session.completedTaskIds`（那是会话结束那一刻的快照），所以**会话结束后补勾的也算**
- **独立维度**

### ⑤ 抗干扰 antiDistraction

```
perceptionSessions = finished.filter(s => s.perceptionMode === 'PERCEPTION_FULL')
avgDistr = mean( perceptionSessions.map(s => distractionRate(s)) )
antiDistraction = round( 100 × (1 − clamp(avgDistr, 0, 1)) )
```

- **口径**：只统计**开了摄像头感知**的会话的平均分心率
- 刻意剔除未开感知的会话：没开摄像头时 `distractionDuration` 恒为 0，混进来会把「没数据」算成「抗干扰满分」
- **派生维度**（见第 3 节）

## 3. 三个已知的结构性问题

### 3.1 专注度与抗干扰是同一个量的两种平均 ⭐

由 `专注率 + 分心率 ≡ 1` 可推出：

```
专注度      = round( 100 × ΣnetFocus / Σjudged )
            = 100 − (按时长加权的分心率)

抗干扰      = 100 − (会话等权平均的分心率)
```

**两个都是"100 减去分心率"，差别只是加权方式**——专注度按秒加权、抗干扰按会话等权。当各会话时长差别不大时，这两个数几乎相等，雷达图上两个顶点会始终同向移动。

而且两者的样本集还不同（专注度用全部会话，抗干扰只用感知会话），所以图上看到的差值是**采样偏差**，不是"衡量了不同的东西"。

### 3.2 效率是纯线性组合

```
效率 = 0.6 × 专注度 + 0.4 × 执行力
```

因此五维实际只有 **3 个独立维度**：专注度、执行力、稳定性。

### 3.3 稳定性的"会话等权"会误伤

`σ` 是用**每场会话的专注率**算的，**会话等权**——一次 1 分钟的会话和一次 2 小时的会话权重相同。

而 `专注度` 用的是**时长加权**。两者口径不一致，会出现同一张雷达图上的自相矛盾：

> 一次 2 小时专注率 0.90 的会话 + 一次 1 分钟专注率 0.20 的会话
> → σ ≈ 0.35 > 0.3 → **稳定性 = 0**
> → 但专注度 ≈ 90（那次 1 分钟几乎不影响加权值）

用户会看到「专注度 90 / 稳定性 0」，而实际只是刚开始的一分钟分了下心。

## 4. 两个会让数字失真的实现细节

### 4.1 没有任务清单时「效率」被无故压低，且不标缺失

当 `taskCount === 0`（用户只用「自由专注」不规划任务）：

```
committed 为空 → execution = 0
efficiency = round( 0.6 × weightedRate + 0.4 × 0 ) = 0.6 × weightedRate
```

即 **效率被强制乘了 0.6**。若专注度是 85，效率就显示 51。但 `dimMissing[0]` 写死为 `false`，页面**不标记这个维度有问题**。

用户看到的是「专注度 85 / 效率 51 / 执行力 —」，完全不知道为什么效率低。

**修法**：`dimMissing[0] = p.taskCount === 0`，或让 `fiveDim` 在 `committed` 为空时把 `efficiency` 标为不可评（返回 −1 哨兵）。

### 4.2 样本量差异不提示

`execution` 可能只由 1 场有任务的会话算出（`taskCount = 1`），`antiDistraction` 可能只由 1 场感知会话算出（`perceptionCount = 1`），而 `concentration` 由全部 N 场算出——**但雷达图上五个顶点看起来同等可信**。

`coverageNote()` 只在 `=== 0` 时提示，`=== 1`（拿一次会话下结论）不提示。

## 5. 如果要改，建议的方向

| 维度 | 现状 | 建议 | 已有数据来源 |
|---|---|---|---|
| **效率** | `0.6×专注度 + 0.4×执行力` | 改为真正的"单位时间产出"：`Σ已完成任务的预估分钟 / Σ实际投入分钟`，clamp 到 100 | `Task.estimatedDuration` / `Task.actualDuration`（`actualDuration` 已由 `FocusController:317-356` 按任务归属曲线分段反算写入） |
| **专注度** | `ΣnetFocus / Σjudged` | 保持 | — |
| **稳定性** | 会话等权 σ，硬断崖 | ① 改为**时长加权 σ**，与专注度口径统一；② 断崖改软着陆（σ>0.35 时下限 30）；③ `sampleCount < 5` 标"样本不足" | 会话序列 |
| **执行力** | `已完成承诺任务 / 承诺任务` | 保持（口径正确）。样本 < 3 时标"样本不足" | 任务表 |
| **抗干扰** | `100 − 平均分心率`（≈ 专注度） | 改为**恢复力**：`干预后回到专注的比例`，或 `100 − 单位时长的分心次数归一` | `session.interventions` 的 `recoveredFocus` / `userFeedback`（`InterventionEngine.recordUserFeedback()` 已在采集） |

> ⚠️ 改口径会改变已落库画像的数值含义。建议加 `profileVersion`，老数据标记"口径已更新，重新积累"，**不要新旧混算**。
