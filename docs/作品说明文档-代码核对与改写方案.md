## 0.1 关键澄清：识别走的是**云端多模态**，不是端侧；"模拟"只是演示权宜

这一条会改变整篇文档里"识别"部分的写法，务必先对齐：

- **代码的核心识别路径是云端多模态大模型**：触发时抓拍帧 → base64 → POST 给视觉模型（`GatewayAIService.ets:276-320`）。`FocusController` 直接称结果为"**云端识别结果**"（`:1247`、`:864`）。
- `FocusTuning.ets:160-165` 白纸黑字："**全部帧都上传云端识别**（多帧更准），本地只留 1~2 张代表帧"。
- 没有结论时的 evidence 文案就是"**已上传 N 帧，云端未返回可用结论**"（`ObservationQueue.ets:174`）。
- **为什么现在只能是模拟识别——两层原因**：
  1. **根因（技术卡点）**：演示设备上真实抓拍**取不到帧**，`CameraService.captureBurst()` 返回空数组（`photoAvailable` 不回调 / 编码非 JPEG）⇒ **没有画面上传** ⇒ 云端识别无输入。详见根目录 `iKnow-真实抓拍无画面-问题交接.md`。
  2. **演示口径（临时处置）**：采集打通前，按"先不上传真实拍摄的画面、仅用模拟控制台"的口径，把识别器**固定注入本机模拟源**（`FocusController.ets:476`），保证"**识别之后**"的真实链路可稳定演示。
- **与 PRD 的关系**：PRD §7/§15 里摄像头感知原计划走**端侧**（Core Vision Kit，V1），多模态云端原本只给"拍题答疑"用（`PRD:169`、`PRD:549`）；但**落地时把"识别在做什么"也交给了云端多模态**。⇒ 文档既**不能**写"端侧 AI"，也**不能**把云端识别写成"未接线/已关闭"，正确写法是"**云端多模态识别（核心、已实现）**；当前演示因采集未打通以本机模拟源代替，一行可切回"。

### 6.2 核心功能设计：交互逻辑与技术实现路径

**2.1 核心交互逻辑**

完整流程为「目标拆解 → 专注监测 → 智能干预 → AI 答疑 → 数据复盘」五阶段：

- **目标拆解**：AI 任务规划 Agent 自适应追问——信息够（明确动作与数量）即**直接生成计划**，仅在模糊时追问，**最多 3 轮**；生成的清单支持逐条勾选、修改标题/科目/时长、增删。
- **专注监测**：手机摄像头在感知触发时抓拍 2~3 秒画面短片段，交由**云端多模态大模型**识别"在做什么"（做题/看书/看手机/趴桌/离开/多人）；手表经**标准 BLE（HRS）**提供心率与 RR 间期，用于推导 RMSSD/HRV，动作幅度由手机加速度计方差提供。识别的**可观察状态**与生理信号经**本机规则状态机**融合，配合基线比较输出专注状态（RMSSD 仅作"状态变化待确认"线索，不单独下"分心"结论）。
- **智能干预**：颜色**只跟本次分心持续时长走**——检测到即为🟡黄灯（短震 + 文字卡片）；持续 **≥60s 升🔴红灯**（连续震动 + 人格化语音播报一遍）；持续 **≥5min 进入强提醒**（语音循环、震动封顶 30s）。绿灯零打扰。**无手表时走手机提示，绝不假装手表震动。**
- **AI 答疑**：专注中可随时以**文字**提问，答疑时段单独计时并计入复盘"答疑"列与《问题记录》，实现"专注时不分心、答疑时不遗漏"。
- **数据复盘**：结束后生成**单次复盘报告**（总时长/净专注、状态时间线、效率曲线、建议、问题记录）；长期积累 **N≥3** 次后生成**五维个人专注画像**（效率/专注度/稳定性/执行力/抗干扰），未达标显示"还在了解你"。

**2.2 技术实现路径**

客户端基于 **HarmonyOS NEXT + ArkTS/ArkUI（Stage 模型）**原生开发，关键实现如下：

- **信号接入**：`@kit.ConnectivityKit` 蓝牙接入标准 **BLE 心率设备（HRS 0x180D / 0x2A37）**，解析心率与 **RR 间期**并推导 RMSSD/HRV；动作幅度由 `@kit.SensorServiceKit` 手机加速度计提供。
- **画面采集与识别**：`@kit.CameraKit`/`@kit.ImageKit` 在预览会话上连拍短片段；识别统一走 `FrameRecognizer` 接口，**核心实现为云端多模态大模型**（帧经 base64 上传，返回"可观察状态"），另备**本机模拟识别源**用于无相机环境，**一行注入即可切换**——当前演示因真实采集未打通，临时使用本机模拟源。
- **识别源的可替换设计**：`SimulatedRecognizer`（本机）与 `GatewayRecognizer`（云端）实现同一接口，切换只改一处注入（`FocusController.ets:476`），识别失败一律如实记"无法判断 + 具体原因"，**不编造结论**。
- **状态融合**：自研规则状态机（`FocusTuning` + `WatchEventEngine` + `InterventionEngine`），含置信度地板（<50 采而不信）、最小驻留、去抖、升级冷却与干预预算（10 分钟内 2 轻 + 1 重），并支持崩溃/后台恢复快照。
- **AI 能力**：所有 AI 请求经**统一 `AIService` 门面**对接 **OpenAI 兼容 `/chat/completions`**（千问 qwen-plus / qwen-turbo / qwen3-vl），强制 **JSON Schema 校验**、分场景超时与失败重试，网关不可用时**自动回退本地模板**，**AI 失败不影响计时与记录**。
- **本地存储**：`@kit.ArkData` **RelationalStore（RDB/键值表）**保存任务、会话、观察、生理事件与复盘。
- **提醒与触达**：`vibrator` 震动 + 预置人格化录音 + `@kit.FormKit` **元服务卡片**（今日卡/长期卡）。
- **隐私合规**：分项授权、触发式一次性识别、一键清除、AI 身份透明（见 2.3）。

**2.3 合规与隐私保护**

参照《人工智能拟人化互动服务管理暂行办法》，iKnow 落地四项：

- **身份透明**：界面固定显示「💡 AI 智能体」标签，首次使用弹窗明确告知"小伴是 AI，不是真人"。
- **分项授权**：相机 / 心率设备 / 震动独立授权，弹窗**不打包勾选**；未授权自动降级为"仅计时模式"并如实标注。
- **数据最小化**：画面短片段**仅在感知触发时上传做一次性识别**，云端只返回可观察状态、不留存；**生理数据不出设备**；本机仅保留 1~2 张代表帧（保留期 7 天）。
- **数据删除权**：支持**分项清除**（学习数据 / 画面片段 / 生理数据）与**一键清除全部**，清除不可恢复。
