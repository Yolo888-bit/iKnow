**当前版本的「闭环」只在理想路径上成立。** 用户做任何一次计划外动作（按系统返回键、专注中完成一个任务、清数据、切后台、跨天再来），闭环就会断——而且**大多是「静默错误」：不崩溃、不报错，但数据是错的或冻结的**。评委演示时看不到红字，只会看到「净专注率 0%」「完成率 0%」「休息后计时器不动了」。

## 2. 全场景审计

### 2.1 用户旅程与断点地图

```
【首次安装】
 冷启动 → 种子数据写入(7条假会话 + 10条假任务 + 假画像)
      ↓
 ┌─ 首页 ─────────────────────────────────────────┐
 │ 问候 / 圆环(0%) / 今日任务 / 开始专注 / AI建议   │ ← E2 圆环恒 0
 └────────────────────────────────────────────────┘
      ↓ 开始专注（无计划）
 【AI 规划】对话 2 轮 → 生成 4 个任务
      ⚠ 用户输入的「2 小时」被丢弃（E11）
      ↓ 确认计划
 【专注中】计时器 + 呼吸灯 + 绿/黄/红
      ⚠ 无法勾选完成任务      → E1（最高频行为！）
      ⚠ 无法切换当前任务      → E1
      ⚠ 按系统返回键          → E4 幽灵会话
      ⚠ 切后台/息屏           → A2/E5 计时偏短
      ↓ 答疑
 【AI 答疑】计时继续
      ⚠ 按系统返回键          → E6 QA 永久卡死
      ⚠ 暂停中进答疑再返回     → E7 暂停态丢失
      ↓ 休息
 【休息页】300 秒倒计时
      ⚠ 按系统返回键          → A1 计时永久冻结
      ⚠ 想结束但回不去        → E8 死胡同
      ↓ 结束
 【复盘】总时长/完成率/曲线/洞察/建议
      ⚠ 完成率 0%            → E1
      ⚠ 曲线可能为空          → E12
      ⚠ 最佳时段时长算错       → E13
      ↓ 完成
 【回首页】计划被清空 → "还没有今日计划"  → E1 / E9
      ↓
 【工作台】今日任务 0/N、学科进度几乎不涨  → E10
```

#### E1 · 专注页无法完成任务 → 完成率恒为 0%，且结束后计划被清空 ⭐最致命

**复现**：首页 → 开始专注 → AI 规划 → 生成 4 个任务 → 确认 → 专注页**没有勾选框** → 做完无处标记 → 结束 → 复盘显示「完成任务 0/4」「完成率 0%」→ 回首页「还没有今日计划」。

**代码证据**

| 位置 | 事实 |
|---|---|
| `pages/Focus.ets:89-263` | `build()` 内无任何任务勾选/切换 UI |
| `store/AppStore.ets:293-300` | `togglePlanTask()` 存在，但**只有 Home 调用** |
| `store/AppStore.ets:330` | `endSession()` 末尾 `this.currentPlan = []` —— 计划用完即弃 |
| `services/ReportService.ets:36-41` | `completionRate = completedTaskIds.length / taskIds.length` |
| `services/FocusController.ets:300` | `completedTaskIds` 来自 `tasks.filter(t => t.done)`，无人置 true → 恒空 |

**为什么是 P0**：完成率是 PRD 页面 9 的第一屏核心指标，也是「执行力」维度（B4）的唯一数据源。它恒为 0 = 闭环没跑通。且 PRD 页面 1 明确要求「每一个子任务支持勾选完成 / 查看详情」——这是**需求未实现**。

**解决方案**
1. 专注页底部增加「当前任务」可交互卡片（保持极简，默认收起）：
   - 卡上放勾选圈：点击 → `FocusController.completeCurrentTask()`
   - 勾选后自动切到下一个未完成任务（`advanceTask()`），写回 `AppStore.setCurrentPlan`
   - 上滑展开完整任务列表（P1 可选）
2. `FocusController` 新增：
   - `completeCurrentTask(): void` — 当前任务 `done = true`，记录 `completedAtSec`
   - `switchToTask(id: string): void` — 手动切换，记录 `taskTimeline` 切换点（顺带解决 B3）
3. `endSession()` **不清空** `currentPlan`：未完成任务保留在今日计划（跨会话延续），只在显式「重新规划」或跨天时清空 → 直接复用为 **M4 计划延续**的一半
4. 兜底：`taskIds.length === 0`（自由专注）时 `computeCompletionRate` 不返回 100，返回「—」并显示「本次未设定任务」，避免「自由专注 = 100% 完成」的假象

**验收**：专注中勾选 2 个任务 → 复盘显示 2/4、完成率 50%；结束后回首页，剩余 2 个任务仍在列表。

#### E2 · 首页「净专注率」圆环永远显示 0%，工作台柱状图不刷新 ⭐视觉硬伤

**复现**：首页圆环无论专注多久都是 `0%`；工作台「近 7 天净专注趋势」首次空白，数据更新后也不补画。

**代码证据**

| 位置 | 事实 |
|---|---|
| `components/CircularProgress.ets:16-22` | 只在 `.onReady()` 里 `draw()` 一次，**已核实** |
| `components/BarChart.ets:18` / `RadarChart.ets:19` / `FocusChart.ets:17` | 同上 |
| `store/AppStore.ets:76-87` | `initAppStorageDefaults()` 先写 `FOCUS_RATE = 0` |
| `store/AppStore.ets:419` | 之后 `pushAggregates()` 写入真实值——**但 Canvas 不会重绘** |
| `entryability/EntryAbility.ets:11` | `init()` **未 await**（已核实），`loadContent` 立刻执行 → 首帧必然是 0 |

**根因**：ArkUI 的 `Canvas.onReady` 只在画布就绪时触发一次。`@Prop` 变化会重跑 `build()`，但**不重新触发 `onReady`**，所以 `draw()` 永远停在第一次的值（0）。

**解决方案（三选一，推荐第 1 种）**
1. **给图表组件加 `@Watch` 重绘**（推荐，每个组件 +5 行）：
   ```
   @Prop @Watch('redraw') percent: number = 0
   private ready: boolean = false
   redraw(): void { if (this.ready) { this.draw() } }
   // onReady 里：this.ready = true; this.draw()
   ```
   `BarChart` / `RadarChart` / `FocusChart` 同理（数组用 `@Watch` 也可触发）
2. **彻底方案**：弃用 Canvas，改用 `Progress` / `Polyline` / `Shape` 原生组件，天然响应式；工作量较大但对 C3（一多适配）更友好
3. **最省事**：给 Canvas 外层套 `if (this.version > 0)`，数据到达后再挂载，靠重建触发 `onReady`。脏但能跑

**配套修复**：`EntryAbility.onCreate` 改为先 `await init()` 再 `loadContent()`；或给 Index 加「数据加载中」占位，杜绝首帧空态被固化。

**验收**：完成一次 10 分钟专注 → 首页圆环显示非 0 且与复盘一致；工作台柱状图有柱子。

#### E3 · 点了「清除全部数据」，画像页仍是假的五维高分 ⭐合规硬伤

**复现**：设置/隐私 → 清除全部数据 → 「✓ 数据已彻底销毁」→ 进画像页 → 雷达图仍显示 **82/75/68/86/72**，黄金时段仍 `09:30 - 11:30`。

**代码证据**

| 位置 | 事实 |
|---|---|
| `models/FocusProfile.ets:5-12` | **模型默认值本身就是假数据**：`bestFocusTime='09:30 - 11:30'`、五维 `82/75/68/86/72` |

3. 清除数据时连运行时一起清 → 见 E15

**验收**：新装/清数据后 → 画像页显示空态文案；雷达图区域无数值。

#### E4 · 专注页按系统返回键 → 会话变「幽灵会话」，新计划被静默吞掉

**复现**：专注中按系统返回 → 回首页（计时器**仍在后台跑**）→ 首页仍显示「开始专注」→ 用户重新规划 → 确认 → 进专注页 → **计时器是上一段的累计时间，新计划根本没被加载**。

**代码证据**

| 位置 | 事实 |
|---|---|
| `pages/Focus.ets` | **无 `onBackPress()`**（全工程 grep = **0 处**，已核实） |
| `services/FocusController.ets:108` | `setInterval` 在页面销毁后**依然运行**（单例） |
| `pages/Focus.ets:27-30` | `if (!controller.isRunning()) start(...)` → 幽灵会话还在跑 → **不重启** |
| `pages/TaskPlanning.ets:102-103` | `setCurrentPlan(plan)` + `replaceUrl(Focus)` → 新计划只进 Store，没进 Controller |

**解决方案**
1. `Focus.ets` 增加 `onBackPress()`：不直接退出，弹确认「返回首页（保持计时）/ 结束本次专注」；或默认保持会话（见下条）
2. **首页增加「专注进行中」状态条**（优于弹窗）：`Home` 读 `FocusController.isRunning()`；有会话时按钮变「继续专注 · 42:36」+ 顶部悬浮条 → 同时实现了进程内恢复
3. `FocusController.start()` 加 `force` 语义：`TaskPlanning.confirm()` 后若已有运行中会话，必须先 `finalize()` 落库（或明确丢弃），**不允许静默忽略新计划**
4. 兜底：`EntryAbility.onWindowStageCreate` 检查 RUNNING 孤儿会话（见 A2/E5 快照）并提示恢复

**验收**：专注中返回 → 首页显示「继续专注」；重新规划并确认 → 计时器归零、任务标题为新任务。

#### A1 · 休息态卡死（含 E6 / E7 / E8 合并）· 状态机生命周期治理

**已核实的问题族**——全部是「页面生命周期不归还状态机」：

| 子问题 | 现象 | 证据 |
|---|---|---|
| **A1** | 休息页按系统返回 → `resting` 永久 true，计时冻结 | `FocusBreak.ets:25-30` 只 clearInterval 不调 `endBreak()`；`FocusController.ets:136-140` `tick()` 在 resting 时 return |
| **E6** | 答疑页按系统返回 → `qaMode` 永久 true，净专注不再累积 | `AIChat.ets` 无 `onBackPress()`；`endQA()` 只在按钮里调用；`FocusController.ets:213-221` |
| **E7** | 暂停中进答疑再返回 → 显示绿色但计时不动 | `startQA()` 不检查 `paused`；`endQA()` 无条件置 `FOCUSED`；`tick()` 中 `if (paused) return` 优先 |
| **E8** | 休息页是死胡同：无结束入口，按返回就冻结 | `FocusBreak.ets:37-84` 只有两个按钮 |

**解决方案（统一治理）**
1. **所有子页面归还状态机**：`FocusBreak` / `AIChat` 均增加 `onBackPress()`（先调 `endBreak()`/`endQA()` 再 `router.back()`，返回 true 拦截），并在 `aboutToDisappear()` 兜底
2. **保存进入前的状态**：`stateBeforeQA`，`endQA()` 还原而非硬写 `FOCUSED`；`startQA()` 前置 `if (!running || paused || resting) return`（暂停/休息中不给进答疑，按钮置灰）
3. **给所有状态入口加 `running` 守卫**：`endQA()` 当前**无守卫**，非会话状态调用会误启 `FocusDetectionService`；`pause()/resume()/startBreak()/endBreak()` 现在全都没有
4. **休息态由 controller 独占**：删除 `FocusBreak` 自有的 `setInterval`；新增 `getBreakRemainSec()` / `extendBreak(sec)`；「再休息 5 分钟」调 `extendBreak(300)` 而非只改 `@State`
5. **休息页增加「结束本次专注」按钮** → `AppStore.endSession()` → `replaceUrl('pages/StudyReport')`
6. **统一出口：`FocusController.getSnapshot()`**（见 §3.5）——UI 不再靠 `state` 字符串反推 `running/paused/resting/qaMode`

**验收**：休息/答疑页按返回 → 计时继续；休息页点结束 → 正常出复盘；暂停态不被答疑覆盖；连续 5 次进出休息/暂停/答疑无停摆。

#### A2 · 墙钟计时（含 E5 孤儿会话恢复）

**问题**：`FocusController.ets:129-156` `tick()` 每 1000ms `totalSec++`，**计时 = tick 次数**。后台/息屏漏 tick → 时长偏短。`module.json5` **未声明任何后台模式**（已核实）。这不只是 P1——演示视频必然有「息屏/切出去」的镜头。

**解决方案**：采用 §3.1 的**段（Segment）模型**，并补两点：
1. **段模型 + 周期快照**：状态切换/暂停/答疑/休息时用 `Date.now() - segmentStart` 结算；同时每 30 秒把 `session` 快照写库（新增 `status=RUNNING` 的行）
2. **冷启动孤儿会话恢复**：`AppStore.doInit()` 结束时查 `status === RUNNING` 的会话：
   - `startTime` 距今 < 2 小时 → 首页提示「上次有一段专注没结束（约 42 分钟），继续还是丢弃？」
   - \> 2 小时 → 静默标记 `ABANDONED`，不参与统计
3. `module.json5` 增加 `backgroundModes`（如赛制允许）或改用 `backgroundTaskManager` 做短时任务；**若不可行，段模型已能保证前台切后台再回来时长正确**

**验收**：专注中息屏 60s → 返回后 elapsed 增量 ≈ 60s（±2s）；杀进程重启 → 提示恢复或丢弃。

#### E15 · 清除数据时未停止正在进行的会话

`AppStore.clearAll()` 删表，但 `FocusController` 仍在跑。用户清完数据回到专注页点结束 → **刚删掉的数据又被写回**。
**改法**：`clearAll()` 首行 `FocusController.getInstance().abort()`（新增：停 tick、停检测、清 AppStorage 的 `FOCUS_*` 键、`running = false`）；并提示「正在进行的专注已终止」。

#### E16 · 「结束确认」弹窗无法取消

`Focus.ets:284-332` 的确认弹窗只有「直接结束」「生成复盘」，**没有取消/继续专注**，点遮罩也不关闭。

## 3. 关键设计决策（架构层）

### 3.1 段（Segment）模型 —— 计时与状态的地基

**问题**：计时速记于 tick 次数，且状态迁移散落各处，导致 A1/A2/E5/E6/E7 一群问题。

**模型**

```typescript
class SessionSegment {
  state: FocusState
  startTs: number   // ms
  endTs: number     // 0 = 仍开放
}
```
- 同一时刻**最多一个开放段**（`endTs === 0`），且为数组末元素
- 段只在**关闭**时写死 `endTs`；开放段时长用 `Date.now() - startTs` 现算
- 统一入口 `switchTo(newState)` = 关闭当前开放段 → 追加新开放段

**口径定义**（依据 README：总学习时长 = 净专注 + 分心 + 答疑，休息/暂停不计入）

| 段状态 | 总学习 | 净专注 | 分心 | 答疑 | 休息 |
|---|:---:|:---:|:---:|:---:|:---:|
| `FOCUSED` | ✔ | ✔ | | | |
| `SLIGHTLY_DISTRACTED` / `DISTRACTED` | ✔ | | ✔ | | |
| `QA_MODE` | ✔ | | | ✔ | |
| `RESTING` | ✘ | | | | ✔ |
| `PAUSED` | ✘ | | | | |

**开合规则**

| 入口 | 动作 |
|---|---|
| `start(tasks)` | 建开放 `FOCUSED` 段 |
| 状态提交（去抖后） | `switchTo(新状态)` |
| `startQA()` / `endQA()` | `switchTo(QA_MODE)` / 还原 `stateBeforeQA` |
| `pause()` | 关闭当前段，**不**开新段 |
| `resume()` | `switchTo(FOCUSED)` |
| `startBreak()` / `endBreak()` | `switchTo(RESTING)` / `switchTo(FOCUSED)` |
| `finalize()` | 关闭开放段 |

**累计计算**：`computeTotals(nowTs)` 遍历段按上表归类求和，**不再自增**；`tick()` 只做 ① `pushLive()` ② 每 15s 采样。段数量很少，O(n) 可忽略。

**设计决策：段仅存在于运行时** —— 不落库，`finalize()` 只把派生结果写进 `FocusSession` 现有字段。**收益**：不改表、不改 `StorageService`（乙的文件）→ **零跨轨依赖**。**代价**：进程被杀无法恢复（E5 的孤儿恢复需要落 `RUNNING` 行，需乙配合，故排入 A2）。

**改造步骤（小步，每步独立提交）**

| 步 | 内容 | 验证 |
|---|---|---|
| 1 | 引入 `SessionSegment` + `segments` + `switchTo()`，全部状态入口调用 | 不改行为；segments 正确开合 |
| 2 | 新增 `computeTotals()`，与旧自增**并行跑**，DEBUG 对拍 | 前台使用时两者差 ≤1s |
| 3 | getter 切到 `computeTotals()`，删除自增 | 前台行为不变 |
| 4 | `tick()` 精简为 `pushLive()` + 采样 | UI 刷新正常 |
| 5 | `finalize()` 用 `computeTotals()` 写字段 | 复盘数值正常 |
| 6 | A1 的状态机生命周期治理 | 见 A1 验收 |

> Step 2 的「对拍」是关键保险：**切换口径前先用旧实现证明新实现是对的**。对拍开关保留到阶段 1 结束。

### 3.2 三层记忆 + 主动招呼（Agent 内核 I）

> **核心判断**：记忆系统的价值在「**数据结构**」而非「**模型**」。只要记忆真实，模板 + 真实数据填充就能生成可信的主动招呼，**不需要大模型**；真实 LLM 作为可选增强，并保留无网络的本地兜底文案包。

| 层 | 内容 | 生命周期 | 用途 |
|---|---|---|---|
| **L1 会话内** | 当前任务、本次曲线摘要、最近 3 条答疑 | 本次 session | 答疑上下文、干预文案 |
| **L2 近期** | 7 日趋势、同类任务耗时偏差、近 3 次干预接受率 | 7–14 天滚动 | 判断"此刻该不该提议" |
| **L3 长期** | 五维画像、黄金时段、易分心任务、人格偏好、目标 | 永久，低频更新 | 招呼的"个性"来源 |

**Context Assembly**：按场景装配上下文子集（招呼/答疑/干预/复盘各取不同切片），定义长度预算与无网络兜底。**同时是 B1 干预阶梯的地基**。

**主动招呼**：进入系统即显示（**首页首屏内容块，非弹窗**），数据触发示例：

| 数据触发 | 招呼 |
|---|---|
| 昨日有计划未完成 | "昨天你计划的高数复习还剩 2 个任务，接着来？" |
| 黄金时段 + 无计划 | "你通常在 9:30–11:00 状态最好，现在正合适，来 45 分钟？" |
| 上次对话说过"状态不好" | "上次你说最近有点累。今天先安排轻量复习？" |
| 数据不足 / 新用户 | "第一次见面。告诉我今天想学什么，我来安排。" |

**分档规则**（避免从"贴心"变"唠叨"）：

| 进入时机 | 行为 |
|---|---|
| 当天首次冷启动 | **完整主动招呼** |
| 当天再次进入 | 不重复招呼，仅静默更新概览 |
| 跨天首次冷启动 | 新招呼，含"昨天……" |
| 从专注页结束返回 | 切换为**收尾语境** |
| **专注进行中** | **绝不招呼** |
| 首次安装 | 自我介绍，**必须含身份透明**（「不是真人」） |

**三条防"假智能"规则**：① 每句引用都能溯源到数据；② 一次最多引用 1–2 个事实；③ 提供"为什么这么说"入口。
**语气红线**：不指责、不制造焦虑。连续几天没来**禁止**说"你已经三天没学了"。
**反模式**：不引入向量库/嵌入检索（单用户小数据量，结构化表足矣）；不伪造历史。

### 3.3 干预升级阶梯（Agent 内核 II）

**问题**：三档硬编码，红灯只弹一次固定询问（E19）。「智能适配」「抗干扰」因此没有真实数据来源。

| 级别 | 行为 | 触发（连续分心） |
|---|---|---|
| L0 | 不打扰 | — |
| L1 | 采样加密（无感） | > 10s |
| L2 | 呼吸灯节奏变化（无文案） | > 30s |
| L3 | 边缘柔和光晕（无文案） | > 60s |
| L4 | 一句轻提示 | > 90s |
| L5 | 主动询问（继续/休息/结束） | > 150s |
| L6 | 建议休息并自动结算 | > 240s |

- **预算**：每 30 分钟 `L4+` 合计 ≤ 2 次；超预算降级为无感反馈
- **反馈回收**：记录用户对 L4/L5 的反应 → 写入 **L2 记忆**，用于下一轮阈值微调
- **人格联动**：QUIET 关闭 L4/L5 或大幅提高阈值
- **UI 要求**：红框需支持「忽略」，且不得随状态抖动反复出现消失

### 3.4 跨设备策略

不做真·分布式（无设备可验证）。改为「**设计主张 + 诚实标注的模拟设备 + 单机可演示的鸿蒙特性**」。
- 手表用第二界面/悬浮窗模拟，通过单例桥接服务真实通信，**UI 必须标注「模拟设备」**
- 凑齐「3 个鸿蒙特性」用可验证的：**实况窗 + 服务卡片 + 一多/响应式**；必要时以意图框架兜底

### 3.6 画面采集与上传的隐私口径（2026-09-19 定）

**本质：画面抓拍与上传必须建立在用户授权之上；界面不得出现与实现相反的承诺。**

错的不在"上传"这件事本身 —— 「手表粗筛 → 触发抓拍 → 云端识别在做什么 → 规则组合」这条链路合理且可辩护；
错在此前在**用户做出同意决定的那一屏**承诺了"不上传"，而实现一直在上传。因此口径统一为：

1. **授权点唯一**：首页点「开始专注」时的感知确认弹窗。确认「开启感知」= 授权抓拍并上传云端识别；
   选择「仅计时开始」= 完全不抓拍、不上传。代码侧同步加门：`FocusController.triggerVisualCheck()`
   未获摄像头授权直接返回（授权是采集与云端识别的前提）。
2. **不设独立的「画面采集与上传」开关**（默认同意）。隐私页只如实说明链路与撤回方式。
3. **文案只陈述可核对的事实**（抓拍了什么、存在哪、怎么删），一律不写「不上传」「不出端」「只在本机」
   这类与实现相反的承诺；上传事实统一由「隐私与数据」页说明。
4. 涉及数据流向的文案清单：`Home.ets` 授权弹窗、`Focus.ets` 预览说明、`Login.ets` 首屏、
   `DeviceService` 设备状态行、`string.json` 的 `reason_camera`（**系统权限弹窗**里显示的那句，最容易被漏）。
   改动文案时须同步核对这 5 处。

  推迟处理 —— 但已泄露的 Key **仍应尽快到控制台吊销轮换**，且不要在后续提交里再带 Key。

- **背景**：`currentPlan` 纯内存 → 冷启动恒显示「还没有今日计划」（E9）
- **首页公式**：`AI 此刻提议（主角） + 克制的今日概览条 + 开始专注（出口）`，对齐 PRD 三要素（今天学什么 / 状态如何 / 是否开始）。**不做成对话界面，也不做成数据面板**
- **改法**：① 首屏呈现招呼（分档见 §3.2）② 今日计划落库（`Task` 加 `planDate`）③ 同一天重启原样恢复；跨天未完成 → **询问**顺延/重规划，**不擅自顺延** ④ 规划入口分层：有今日计划 → 直接进专注；无 → 对话式规划
- **验收**：冷启动出现基于真实数据的招呼；当天再次进入不重复；跨天出现"昨天…"；重启后今日计划仍在；专注中不被打断

#### M5 · 对话接入记忆 ⬜
- **改法**：`AICompanion` / `AIChat` 对话时装配 L1–L3
- **验收**：能准确引用近期事实（引用错误视为不通过）
