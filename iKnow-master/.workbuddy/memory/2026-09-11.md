## iKnow — ArkTS 编译错误修复（84 个）

真实 hvigor 编译报 84 个 ArkTS 错误，根因是 Phase 0/1 代码用了标准 TS 写法，而 ArkTS 严格禁止。已修复 8 个文件：

### ArkTS 合规红线（本项目必守）
- 禁用 `any` / `unknown`：校验器入参改用 `Object`，用 `as <具体接口>` 显式转换。
- 禁用对象字面量类型别名（`type X = {a:string}` / 内联 `: {…}` / `Record<K,V>`）：一律改成 `interface`/`class`；`Map<AIScene, RetryConfig>` 替代 `Record`。
- 禁用类型谓词 `x is T`（`arkts-no-is`）：用 `instanceof`/`as` 或字段逐一 `typeof` 校验。
- 禁用 `this` 出现在 static 方法/回调（`arkts-no-standalone-this`）：ArkTS 不允许静态方法里用 `this`，一律用类名 `Metrics.xxx`。
- 禁用动态字段索引 `obj[key]`（`arkts-no-props-by-index`）：`PermissionService` 用 `switch` 显式映射 `AuthKind`；文案表 `Record<string,Record<...>>` 改为 `WordingMap` 接口 + `wordingFor` switch。
- 禁用匿名对象字面量作返回值（`arkts-no-untyped-obj-literals`）：返回值必须对应已声明接口/类。
- 禁用 `类 = 类` 当对象（`arkts-no-classes-as-obj`）：`SchemaValidator` 直接 `export class` 并以静态方法分发，不再 `export const X = Validator`。
- 泛型 `as T` 强转可能不被允许：兜底数据改为"具体类型默认对象 + 调用点传入"，彻底去掉 `as T` / `as unknown as T`。
- `catch` 子句**禁止任何类型标注**（实测本 SDK 版本：`catch (e: Object)` 与 `catch (e: unknown)` 均报错，分别触发 `arkts-no-types-in-catch` 和 `arkts-no-any-unknown`）。正确写法：**裸 `catch (e)`**，函数体内若需访问异常可 `e as <接口>` 后使用。
- `Map` 构造用 `new Map<K,V>([...])`，避免 `Record` 与对象字面量类型。
- 修完需 `Build → Clean Project → assembleHap`（务必清 `entry/build` 旧编译缓存）。

## iKnow — 第二轮 ArkTS 编译错误修复（10 个，Phase 1 引入）

首次 `assembleHap` 通过（0 ERROR）后，二次编译报 10 个 ERROR（116 WARN 非阻断）。根因：Phase 1 改 `SchemaValidator`/`MockAIService` 时部分 ArkTS 写法仍违规，二次编译才暴露。

修复点：
1. `SchemaValidator.ets`：`SceneValidator` 原是 `interface`，5 个校验器返回含方法的对象字面量 → 触发 `arkts-no-untyped-obj-literals`（带方法的对象字面量无法用结构化类型匹配接口）。改为 `export class SceneValidator`（构造函数接收 scene/version/validate 函数属性），5 个 `xxxValidator()` 用 `new SceneValidator(...)` 返回。
2. `MockAIService.ets:241`（后移位到 245）：`catch (e: Object)` → 实测非法 → 改为裸 `catch (e)`（见上方红线第 11 条）。
3. `MockAIService.ets:467`：`dialog()` 兜底数据误用 `this.defaultPlan()`（返回 `PlanningResult`），与 `PlanningDialogResult` 不兼容（缺 reply/done）→ 新增 `defaultDialog()` 返回 `PlanningDialogResult`，替换兜底。

结果：`BUILD SUCCESSFUL`，0 ERROR。剩余 116 WARN 为既有弃用 API（pushUrl/back/showToast/@Entry export）与 StorageService/Home "可能抛异常" 提示，不阻断构建，未动。
