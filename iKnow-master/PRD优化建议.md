| 维度           | 现状评价 | 说明                                                                        |

| 产品愿景       | ★★★★★    | "AI 主动感知而非等待操作"、"有事有人味但不装真人"的定位非常清晰，差异化成立 |
| 交互与 UI 规格 | ★★★★☆    | 页面级描述充分，缺少状态级（加载/空/错误/中断）规格                         |

## 二、缺陷清单（P0/P1/P2）

### P0 — 影响产品成立性，必须在 PRD v2 里定死

**B-1｜AI 人格是"死选项"，完全没有作用于任何一句文案**

- 现象：`AIService` 有 `setPersonality()`，但 `chat / answerQuestion / reviewInsight / proactive / longTermAnalysis` 全部返回固定文案，**没有任何人格分支**。严格教练型与极简安静型输出完全一致。
- 追加问题：App 重启后 `AppStore.doInit()` **没有调用 `AIService.setPersonality(user.aiPersonality)`**，人格变量回到默认 GENTLE（DB 里存了，运行时丢了）。
- 智能化最后一项"智能适配"完全未实现（PRD 承诺"自动调整提醒频率/语气/专注时长/休息时间"）。

**B-2｜隐私页的分项授权是纯 UI 假开关，与合规承诺直接冲突**

- 现象：`Privacy.ets` 的 `allowCamera / allowMic / allowHealth` 都是组件 `@State`，不落盘、不被任何 Service 读取。关闭"允许摄像头"后，`Focus` 页照常显示"摄像头感知中"并启动 `FocusDetectionService`。
- 性质：PRD 第 15 节承诺"分项授权，不支持一键全部授权"，当前实现会让产品在合规审查中被判定为**虚假声明**。
- PRD 需补：**授权状态是全局唯一的系统事实源**，`FocusDetectionService` 必须做前置门禁；关闭摄像头需定义降级模式（仍能计时，但无状态感知、UI 明确标注"本次未开启感知"）。

**B-3｜无真数据却展示漂亮数字（虚假数据）**

- `FocusProfile` 类字段有默认值 `efficiency=82 / concentration=75 / stability=68 / execution=86 / antiDistraction=72`，用户一次都没学习，画像页照样显示一张饱满的五维雷达图。
- `monthlyTrend` 由 `AppStore.genMonthlyTrend()` 随机游走生成，与真实会话无关，且 `updateProfile()` 之后**再也不更新**。
- `bestFocusTime`（黄金专注时段，PRD 的核心卖点之一）永远是种子常量 `'09:30 - 11:30'`，从未计算。
- PRD 需补：**空态规范** + **每个指标的精确计算公式**。少于 N 次会话时画像页应显示"还在了解你"而非伪装成结论。

**B-4｜计时依赖 `setInterval` 累加，息屏/后台必然走偏**

- `FocusController.tick()` 每 1000ms 自增秒数。应用退后台、息屏、系统挂起都会导致漏 tick，`totalDuration` 小于真实墙钟时间，`focusRate` 随之失真。
- 正确口径应为 `Date.now() - startTime` 差值驱动，段落时长按采样点归属。
- 连带：**会话中断无恢复**。杀进程 / 崩溃后本次专注全部丢失，无任何中间落盘。
- PRD 需补：计时口径定义 + 后台/中断/崩溃恢复的非功能需求（HarmonyOS 下建议用长时任务 + 周期性快照）。

### P1 — 影响核心体验，PRD 需要补规格

**C-1｜状态机缺去抖与时长阈值，`confidence` 采而不信**

- `FocusController.onDetection()` 直接透传检测结果的 `target` 状态，没有"持续 X 秒才升级/降级"的判定；`FocusEvent.confidence` 落了库但从未被任何逻辑读取。
- 后果：真实摄像头必然有抖动，会造成 UI 绿↔黄↔红高频闪烁——这正是 PRD 第六节"用户专注时系统尽量不要打扰"的反面。
- `stateSinceSec` 字段在自增却从未被消费（死代码 + 缺失的去抖逻辑已成事实）。
- PRD 需补：**状态转换参数表**（升级阈值、降级阈值、最小驻留时长、置信度过滤阈值、连续 N 次同判才迁移）。

**C-2｜任务维度数据几乎全空，导致"任务级归因"这个最重要的 AI 洞察无法做**

- `Task.actualDuration` 有字段、有 DB 列，**从未被赋值**（恒为 0）。
- `Task.sessionId` 从未被赋值（`AppStore.endSession()` 里 `saveTask(t)` 时该字段仍为空串），无法从会话反查任务。
- `FocusSession` 记录了 timeline（全局），但没有记录"第几分钟在哪个任务上"。
- 后果：AI 永远说不出"你的数学练习题每次第 20 分钟就崩"这类真正有价值的洞察，只能复述本次总时长。
- PRD 需补：**任务级时间归因模型**（taskTimeline / 任务切换事件），并明确"最容易分心的任务"的计算依据（当前 `FocusProfile.hardestSubject()` 用的是学科任务完成率最低者，语义完全不对——那是"进度最慢"不是"最容易分心"）。

**C-3｜FitProfile 五维算法与指标语义不符**

- `stability = 60 + avgFocusMin * 0.4` → 这是"专注时长的线性函数"，与"稳定性（波动程度）"无关，应为多次会话净专注率的**方差/标准差反向映射**。
- `execution = 78 + count * 1.5` → 会话数增长会迅速打满 98，失去区分度。
- `concentration / efficiency / antiDistraction` 三个指标都由同一个 `overallRate` 派生，雷达图五边形必然高度自相似，"看起来很专业但没有信息量"。
- PRD 需补：**五维定义表**（业务含义、计算公式、数据依赖、最小样本量、取值范围、更新时机）。

**C-4｜休息/暂停的所有权混乱**

- `FocusBreak` 页自己起了一个 `setInterval` 倒计时，`FocusController` 也在累加 `breakSec`，**两套计时互不同源**；再休息 5 分钟只重置了页面状态，控制器侧不受影响。
- 用户从休息页直接返回（系统返回键而非"继续专注"），`FocusController.endBreak()` 不会被调用 → **卡死在 RESTING 状态**，tick 里 `if (this.resting) return` 会让整个会话计时停摆。这是可复现的真实卡死路径。
- PRD 需补：**会话生命周期状态图**（含所有出口边：返回键、息屏、来电、卸载重装）。

### P2 — 打磨项

**D-1｜`Dashboard` 的 BarChart 周标签写死 `['一'…'日']`**，与 `computeWeekTrend()` 按"过去 7 天"的口径不匹配（周一开局时会错位）。
**D-2｜"今日任务完成数"按 `Task.createdAt` 统计**，而计划任务要等 `endSession()` 才入库，导致专注过程中首页计数不更新；种子数据下今日任务数恒为 0（种子 `createdAt` 均落在昨天）。
**D-3｜对话式规划丢弃了用户的后两轮回答**：用户回答的"有多少时间""优先哪部分"从未参与 `planTasks()`，生成结果恒为 4×30=120min，与用户说的"两小时"无关。PRD 第二节的核心对话逻辑被架空。
**D-4｜`refreshAggregates()` 每次全表扫描 sessions/tasks**，数据量增长后有性能隐患，且 `Dashboard.weekTrend` 与 `FocusProfile.weeklyTrend` 两套同源不同步的趋势数据。
**D-5｜无目标编辑入口**：用户永远改不了考试类型与目标日期（只有 seed 时写死）。
**D-6｜AI 答疑无失败态/无重试/无免责声明**：真实大模型接入后必然超时失败；学习场景下错误答案是高危害内容。
**D-7｜`SensorService`（Mock 手表）实现完整但从未被任何业务逻辑消费**，设备页显示的心率/HRV 是临时随机数。

## 三、五个战略级产品漏洞（PRD 最该补，但写代码前补收益最大）

### ① 致命的拓扑漏洞：感知端与干预端在同一个屏幕上

产品的核心假设是"手机摄像头看着你学习"。但用户专注时**视线在书本/屏幕上，不在手机上**。当前所有干预（光晕、询问、AI 文案）都渲染在手机屏上——**用户根本看不到**。这是这套产品逻辑里最大的悖论。

> PRD 需新增《设备拓扑与干预通道》章节：
>
> - 明确 **感知端（手表/摄像头）** 与 **受理端（手机/手表/平板/PC/桌面设备）** 的分离拓扑
> - 定义每种干预在不同通道的降级映射：手表触觉 → 桌面指示灯 → 手机 OCR...（例：手表振动 → 手机屏可交互 → 无外设时仅记录不打扰）
> - 明确 MVP 在"无手表"情况下的诚实降级（不是假装振动，而是 UI 明示 + 提供购买/连接引导）

### ② 缺" escalation ladder（干预升级阶梯）"——这是 Agent 感的核心

现在只有三档硬编码。真正的 Agent 化应该是：

```
忽视 → 采样加密 → 呼吸节奏加快（无文案） → 边缘柔光（无文案） → 一句轻提示
     → 一次振动 → 主动询问 → 建议休息并自动结算
```

并且每一步都要**预算控制**（单位时长内最多打扰 N 次）与**反馈回收**（用户忽略/接受/结束，写回策略参数）。这才是"智能适配"和"五维里的抗干扰"真正的数据来源。

> PRD 需新增《干预策略引擎》章节：含升级阶梯表、干预预算表、反馈信号定义、冷启动默认值。

### ③ 缺 Context Assembly（上下文装配）规格

"AI 主动感知"要落地，必须明确每次 LLM 调用喂什么。建议 PRD 定义三层记忆：

- **L1 会话内**：当前任务、本次曲线摘要、最近 3 条答疑（短、高频）
- **L2 近期**：7 日趋势、同类历史任务的实际耗时偏差、近 3 次干预的接受率（中频）
- **L3 长期**：五维画像、黄金时段、易分心任务类型（低频、缓存）
  并规定 token 预算、缓存失效条件、以及**无网络时的本地兜底文案包**。

### ④ 缺"感知质量"本身的验收标准

产品的可信度完全取决于"它判断得准不准"，但 PRD 通篇没提：

- 分心判定的准确率 / 召回率 / **误报率容忍上限**（用户体验上，误报比漏报伤害大得多）
- 不同光照、角度、戴眼镜/口罩、多人入镜下的表现要求
- 采样频率与单次推理耗时/功耗预算（摄像头常开的发热与耗电是这个 App 的生死线）
- 用户手动纠正（"我没走神"）的回收通道
  > 建议 PRD 新增《感知管线技术规格》+《非功能需求》两章，并配一张"误报预算"表。

### ⑤ 缺成功判据：什么是"做好了"

PRD 最终目标是"有真实产品感的原型"，但没有可判定标准。建议定义北极星指标与护栏指标：

- 北极星：**周活跃专注会话数 / 人**
- 关键结果：次日回访率、单次会话中位时长、干预后 5 分钟内回到专注态的比例（这是"干预有效"唯一的直接证据）
- 护栏：误干预率（被判定分心但用户手动纠正的比例）、单次会话感知耗电占比、用户关闭感知的比例

## 四、PRD 结构重构建议（v2 目录）

现有 PRD 是"页面说明书"（第 4 节写了 11 个页面占全篇 45%），建议改为"双轨结构"：**稳定的规格章节 + 可变的体验描述**。

```
0.  文档约定、目标 / 非目标（明确 MVP 不做什么）
1.  背景与机会：用户画像、典型场景、竞品差异
2.  产品定位与成功判据（北极星 + 护栏指标）
3.  用户体验全景：用户旅程地图 + 会话生命周期状态图（含所有异常出口）
4.  信息架构与导航
5.  功能规格 FR-01…FR-nn
     每条 = 描述 + 前置/后置条件 + 验收标准（Given/When/Then）+ 埋点
6.  核心算法规格（本 PRD 的重心，建议占 25% 篇幅）
     6.1 感知管线与状态机参数表
     6.2 干预策略引擎（升级阶梯 + 预算 + 反馈闭环）
     6.3 AI Context Assembly 三层记忆
     6.4 指标口径字典（净专注率/完成率/五维/专注阈值的精确公式）
7.  数据模型与埋点字典
8.  非功能需求：功耗、性能、稳定性、兼容性、无障碍
9.  隐私合规与安全（含授权门禁、本地推理、遥测边界、AI 内容免责）
10. 风险、依赖与开放问题
11. 里程碑、验收清单与 Mock→Real 替换矩阵
附录 A：状态转换表　B：文案语气手册（含负面清单）　C：Service 接口契约　D：术语表
```

## 五、建议优先补写的六段内容（含要点）

### A. 《指标口径字典》（成本最低、收益最高）

至少钉死这 9 个：总学习时长、净专注时长、**分心时长是否包含暂停**、答疑时长的归属、休息时长归属、净专注率分母、完成率（按任务数 or 时长 or 权重）、专注阈值、五维各自公式与最小样本量。

> 现状：代码里 `focusRate = focusDuration / totalDuration`，`completionRate = 已完成任务数 / 总任务数`，两者口径不一致（一个按时长一个按数量），却在同一张复盘卡片上并列展示——用户一定会困惑。

### B. 《感知管线技术规格》

摄像头采样帧率、推理频率、端侧方案选型（Core Vision Kit / MindSpore Lite）、单帧处理耗时预算、每小时耗电预算、光线/角度校准流程、失败降级（不可用 → 仅计时模式）。

### C. 《干预策略引擎》

见 §三-②。同时定义"极简安静型"人格在引擎层面到底关掉哪几级（不是换个说法，是真的少打扰）。

### D. 《AI 内容与安全边界》

免责声明（"答案仅供参考，建议核对教材"）、错误处理/超时/重试的 UI 规范、禁止生成的内容类型、tone 负面清单（现有 PRD 只给了反面例句，建议升级为可检查的规则清单）。

### E. 《空态、加载态、错误态、中断恢复规范》
